## どんなサイトか

公開側にはWorks、Gallery、Blog、About、Fluxを用意し、管理画面からプロフィール、作品、写真、記事、画像、PDFを更新できます。公開画面は余白と文字組を中心にした静かなアーカイブとして設計し、モバイルでは専用のハンバーガーメニューへ切り替わります。

Fluxは、来訪者のローカル時刻と二十四節気に合わせた日本の伝統色を眺めるページです。各節気に朝・昼・夕・夜の4組を持ち、計96セット・48色から、季節と時間帯に合う色と短い文章をブラウザーだけで選びます。同じ節気の約半月は同じ4組で循環し、次の節気でローテーションが変わります。背景のゆっくりした漂い、分ごとの時計、色の切り替えの重なりをCSSで表現し、動きを減らす設定にも対応しています。[Fluxの仕組み](docs/FLUX.md)、[全96セット](docs/flux-palettes.md)、[元の24セットの正本](docs/flux-sekki-colors.md)を公開しています。

BlogにはTiptapを使ったノート風の編集画面を用意しています。行頭の`#`や`-`に続けてスペースを入力すると、見出しや箇条書きへ切り替わります。全角の記号・数字・スペースにも対応し、引用・コード・区切り線、取り消し・やり直し、本文画像の挿入も扱えます。記事は従来のHTMLとして保存し、公開時の安全な整形処理を通します。編集コードはBlogタブを開いたときだけ読み込みます。[入力方法と実装](docs/BLOG-EDITOR.md)に詳しく記載しています。

Homeの「制作と日々の記録」は、各カテゴリの最新記録を優先した1行のプレビューです。画面幅に応じて1〜4件を表示し、投稿数の多いカテゴリだけが並ばないように選びます。記録の一覧はそれぞれのカテゴリページで閲覧できます。

Aboutの名前・アイコンを押すと、プロフィール情報を載せた搭乗券が、上部のプリンターから送り出されます。PCでは本券と半券が並ぶ横長の紙面、スマホでは縦配置に切り替えます。サイトのQRコード、2026年10月11日の公開日、X・GitHubのIDを載せ、動きを減らす設定やキーボード操作にも対応します。出発地は、開いたときに接続元IPをIPWhoisへHTTPSで照会して推定します。取得した地域は搭乗券表示にだけ使い、この機能から他の第三者へ提供しません。ページ下部にも取得先・目的・一時保存の説明を掲載しています。[プロフィール搭乗券の仕組み](docs/PROFILE-BOARDING-PASS.md)に実装をまとめています。

Galleryでは、元画像のEXIFから撮影日時、カメラ・レンズ、焦点距離、絞り値、シャッタースピード、ISO感度を自動入力します。単枚・一括アップロードの両方に対応し、読み取った値は編集可能です。撮影情報は画像とは別にDBへ保存し、公開Galleryの詳細にも表示します。使用方法と日時の扱いは [Galleryの撮影情報](docs/GALLERY-EXIF.md) を参照してください。

Aboutの音楽欄は、普段聴いている曲をアーティスト別に整理した一覧です。曲名とカバー・バージョンを文字中心に表示し、アーティスト名を開くとYouTubeへのリンクを閲覧できます。ライブラリーの資料と整理基準、管理画面での編集方法は [音楽ライブラリーの記録](docs/MUSIC-LIBRARY.md) にまとめています。

Aboutの使用機材には、パソコン、スマートフォン、タブレット、音楽機器、カメラ、その他の道具を登録できます。種類に応じた仕様、組み合わせ、用途・使い心地、写真を管理画面から編集でき、公開ページにも種類別に表示します。従来のパソコンデータはそのまま使用でき、種類未設定のデータはパソコンとして扱います。追加のデータベース移行は不要です。

バックエンドには、個人サイトの更新頻度と規模に合うPHPとSQLiteを採用しています。外部CMSやクラウドDBを増やさず、サイトのデータ、ログイン状態、アップロードメディアをXServer内で管理する構成です。

## 技術構成

Node.jsはローカルでのフロントエンドビルドとテストにだけ使います。公開環境でNode.jsのプロセスを常駐させる必要はありません。

## アーキテクチャ

```mermaid
flowchart LR
  Browser[閲覧者・管理者のブラウザ]
  Static[Reactの静的ファイル<br/>HTML / CSS / JS]
  Api[PHP API<br/>/api/trpc]
  Db[(SQLite)]
  Session[PHPセッション]
  Uploads[画像・PDF]
  Geo[IPWhois / ipwho.is]

  Browser -->|公開画面| Static
  Browser -->|JSONで取得・保存| Api
  Api --> Db
  Api --> Session
  Api --> Uploads
  Api -->|搭乗券を開いたときだけ接続元IPをHTTPS照会| Geo
  Geo -->|都市・地域・国| Api
```

Reactのクライアントは同一ドメインの `/api/trpc` にJSONリクエストを送ります。PHPは受け取った手続きを振り分け、SQLiteを読み書きして、SuperJSONのメタデータを含むレスポンスを返します。フロントエンド側の型付きクエリとキャッシュの扱いを維持しつつ、レンタルサーバーで動くPHP実装に置き換えるためのアダプターとして設計しています。

管理画面の更新も同じ経路です。ログイン済みのブラウザからPOSTされたデータをPHPが検証し、SQLiteへ保存します。公開ページでは公開状態のレコードだけを返します。

搭乗券の出発地取得だけは外部のIPWhoisを使用します。GPSは使わず、ブラウザへは都市・地域・国だけを返します。取得できない場合は「YOUR CITY」に切り替え、搭乗券の表示とQRコードの利用を続けられます。照会結果は非公開セッションに一時保存し、プロフィールや投稿には保存しません。

## データとファイルの置き場所

公開ディレクトリと、公開してはいけない情報を分けています。

```text
<XServerの契約領域>/
  portfolio-private/                 # HTTPから到達しない領域
    config.php                        # 許可オリジン、管理者パスワードハッシュ
    portfolio.sqlite                  # コンテンツと運用データ
    sessions/                         # PHPログインセッション
  public_html/                        # 公開ディレクトリ
    index.html
    assets/                           # Viteが出力するハッシュ付きアセット
    api/                              # PHP API
    uploads/                          # 管理画面から追加した画像・PDF
    .htaccess                         # SPA/APIのルーティング
```

SQLiteにはプロフィール、Works、Gallery、Blog記事、訪問者名、コメント、いいね、レート制限のカウンターを保存します。廃止したBooksの旧レコードも保管したままですが、公開・管理APIからは利用しません。画像・PDFはデータベースへ直接格納せず、`uploads` にランダムな名前で保存し、コンテンツ側にはそのURLを持たせます。これにより、DBのバックアップとメディアのバックアップを独立して扱えます。

`PORTFOLIO_PRIVATE_DIR` を設定すれば、プライベート領域の位置を環境に合わせて変えられます。

## メディア処理と安全性

画像アップロード時は、ブラウザ側の最適化に加えてPHP側でもMIMEタイプと解像度を確認します。GDで最大辺1600pxに縮小・再エンコードし、対応環境ではより小さくなる場合にWebPを使います。PDFはサイズ、MIMEタイプ、ファイルシグネチャを確認してから保存し、ブラウザでの直接実行ではなくダウンロードとして配信します。

管理者認証にはPHPのパスワードハッシュとサーバーサイドセッションを使います。更新系のAPIはPOST、同一オリジン確認、専用ヘッダーを要求し、ログイン、コメント、いいねにはSQLiteに記録するレート制限があります。セッションCookieには `HttpOnly` と `SameSite=Lax` を付与し、HTTPSでは `Secure` も有効になります。

## 運用の考え方

ビルドでは、初回設置用の `dist/public` と、継続更新用の `dist/update` を分けて生成します。Windowsでは更新用の `dist/update.zip` も生成します。更新パッケージには静的ファイル、PHP API、ハッシュ付きアセットだけを含め、投稿画像が入る `uploads` は含めません。

更新は既存の `public_html` にパッケージの中身を上書きする方式です。公開フォルダ全体の削除・置き換えや、ローカルにないファイルを削除する同期は行いません。`portfolio-private` と `uploads` が持つコンテンツと運用状態を保持するため、アプリの配布物とサーバーで増えるデータを分離しています。更新と画像復旧の手順は [XServer運用ガイド](docs/XSERVER.md#継続更新と画像の復旧) にまとめています。

バックアップでは、SQLite、`uploads`、プライベート設定を一組として扱います。コンテンツだけを移す場合には、`xserver/manage.php` がJSON形式のexport/importを提供します。SQLiteを使うことで、個人ポートフォリオに必要な単一サーバー上のシンプルさと、データの持ち運びやすさを両立しています。
