# プロフィール搭乗券とBooksの廃止

Aboutページの名前、または丸いアイコンを押すと、プロフィールを載せた搭乗券を発行します。航空会社の紙の搭乗券をイメージし、上部のプリンターのスロットから紙が送り出される演出を付けています。

## 掲載する情報

- 名前・アイコン：管理画面のプロフィール設定から取得
- サイトURL：`https://tukiharu.xsrv.jp/`
- QRコード：同じ公開サイトURLを端末内で生成。QR生成のために外部サービスへ送信しない
- サイト公開日：2026年10月11日
- X・GitHubのID：プロフィールのSNS URLから取得。未設定の場合は「未設定」と表示
- 出発地：搭乗券を開いた訪問者の接続元IPから推定した都市・地域。取得できなければ「YOUR CITY」

サイトURLと公開日は[shared/site.ts](../shared/site.ts)で管理しています。SNSリンクはサービスの正しいHTTPS URLだけを使い、余分なクエリや投稿のパスを取り除いてプロフィールへリンクします。

## 実装と操作

[BoardingPass.tsx](../client/src/components/BoardingPass.tsx)で、SVGの紙の輪郭とQRコード、選択・読み上げできるHTMLのプロフィール情報を組み合わせています。[boarding-pass.css](../client/src/boarding-pass.css)のCSSアニメーションで紙を上から送り出します。閉じて開き直すと、もう一度発行できます。

印刷部分は見えている範囲を切り取るため、紙がプリンターの外側から現れるように見えます。音の自動再生や常時動作する演出は追加していません。QR生成と搭乗券のコードは最初に発行するときだけ読み込みます。

名前・アイコンは通常のボタンで、キーボードのEnter・Spaceでも開けます。ダイアログはEscape・閉じるボタン・背景クリックで閉じ、開いたボタンへフォーカスを戻します。`prefers-reduced-motion: reduce`では、印刷アニメーションを省略して完成した搭乗券を表示します。高さが足りない画面ではダイアログ内をスクロールできます。

QRは[qrcode](https://github.com/soldair/node-qrcode)のモジュール配列からSVGパスを生成しています。周囲に4モジュール分の余白を確保し、テストでは別ライブラリーのデコーダーで公開URLへ復号できることを確認します。

### 紙面と出発地

PCでは横長の本券＋半券、640px以下では縦配置です。濃紺の航空会社風ヘッダー、便名・ゲート・座席の情報ブロック、ミシン目と切り欠き、半券のQRを使っています。便名や座席はプロフィール用の架空の表現で、「PROFILE SOUVENIR · NOT VALID FOR TRAVEL」と記載しています。日付はサイト公開日です。

地域推定には、所有者が照会先を明示して許可した[IPWhois](https://ipwhois.io/documentation)を使います。`content.departure.get`が呼ばれると、[departure.php](../xserver/public/api/departure.php)がサーバーの`REMOTE_ADDR`を検証し、`https://ipwho.is/<IP>?fields=success,city,region,country,country_code`へHTTPSで照会します。転送ヘッダーやリクエストで指定した任意のIPは信頼しません。ローカル・プライベート・予約IPは送信しません。GPSの取得はありません。

ブラウザへの応答は`status / city / region / country / countryCode`だけです。IPや座標、通信事業者などは返しません。画面上も推定地域として扱い、最寄り空港を推測して空港コードに変えることはしません。VPN・モバイル回線などでは実際の場所と異なる場合があります。

同一IP・セッションの成功結果は6時間、失敗結果は5分間キャッシュします。非公開セッションには地域情報・IPのハッシュ・期限、既存の`attempts`表には照会回数制限用のハッシュ・回数・時刻が残ります。地域情報をプロフィールや投稿に保存する処理はありません。React Queryのキャッシュも同じ有効時間に合わせ、再発行だけで毎回照会しません。

通信はcURLを優先し、利用できない場合はPHPのHTTPSストリームを使います。TLS証明書を検証し、転送先の自動追跡を無効にし、タイムアウトと応答サイズ上限を設けます。障害・提供元の利用制限・不正応答は代替表示に切り替え、搭乗券やQRの操作を妨げません。IPWhoisには利用枠があるため、無制限の地域取得は保証しません。

Aboutページの下部と搭乗券内に、IPWhoisへの送信・搭乗券表示だけの利用・一時保存を説明しています。この機能から取得情報を広告・アクセス解析やIPWhois以外の第三者へ提供する処理はありません。提供元自体の取り扱いや、一般のWebサーバーのアクセスログまで「保存・再利用しない」と保証する表現は避けています。

## Booksの廃止範囲

PC・スマホのナビゲーション、Homeの本のプレビュー、公開本棚、管理画面のBooksタブ、公開・編集・検索API、Google Books検索コードと提供元ロゴを削除しました。`/library`と`/books`は通常の未存在ページになります。

以前の本のレコード、アップロード画像、APIキーなどの保存済み運用データは、この変更で削除しません。旧データのexport/importに必要な互換処理は残し、通常の画面・APIから本を取得する機能は廃止しています。データベースのテーブル移行は不要です。

更新時は[更新パッケージの手順](XSERVER.md)を使います。過去に配信済みの`api/google-books.php`は新しいパッケージに含まれません。現在のAPI入口からは呼び出されませんが、配信ファイルも整理する場合は、この旧ファイルだけを対象にします。`uploads`や非公開DBを削除する必要はありません。

## 検証

2026年10月26日に、型チェック、31ファイル119件のVitest、配布処理3件、PHPの38項目と、実際のPHPを使ったAPI統合検証を実施しました。統合検証で見つかった、バックアップ復元時の音楽初期化フラグの不整合も修正し、公開内容を保持して復元できることを確認しています。

Chromeと分離したSQLiteで、名前・アイコンからの発行、SVGから描画したQRの復号、サイトURL・日付・SNS、閉じる操作とフォーカス復帰、印刷途中と完了状態、動きを減らす設定、320・375・430・768・1024・1440px、タッチ操作を確認しています。Home・ナビゲーション・管理画面にBooksがなく、旧URLが未存在ページになり、保管レコードが残ることも検証しています。公開XServerへの反映と実機Safariの動作は、このローカル検証には含みません。

地域推定では、ローカルIPのPHP応答とキャッシュ禁止ヘッダー、ページ閲覧時に照会しないこと、再発行時のキャッシュ、地域取得失敗時の代替表示を確認しました。制御したAPI応答でTokyo・100文字の長い都市名・通信失敗を使い、6画面幅で文字のはみ出しがないことを検証しています。プライバシー説明もAboutに表示されます。

外部サービスとの実通信は、訪問者や作業PCのIPを使わず、既知の公開DNS IP `8.8.8.8`で行い、PHP/cURLからIPWhoisへHTTPSで照会して地域だけを取得できました。このPCのPHPは初期状態では証明書設定が不足していたため、OSが信頼する公開ルート証明書をテスト専用に指定しました。TLS検証は無効にしていません。cURLなしのHTTPSストリームはこのPCでは接続タイムアウトとなり、実通信の成功は確認できていません。公開XServerからの接続と、実際の訪問者の地域精度は未検証です。
