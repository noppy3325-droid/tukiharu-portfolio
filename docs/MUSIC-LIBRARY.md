# 自己紹介ページの音楽ライブラリー

普段聴いている音楽を、曲名とアーティスト（カバーの場合は歌い手）で整理しています。アーティスト別の一覧を開くと、曲名、バージョン、YouTubeリンクを閲覧できます。ジャケットを一律に並べるカード形式から、文字中心の一覧へ変更しました。

## 整理に使った資料

- 所有者が提供したOne Playerのスクリーンショット10枚（IMG_0956.PNG〜IMG_0965.PNG）。曲名とアーティストの表記を優先しています。
- 所有者が提供した音楽ライブラリーのスクリーンショットPDF（screencapture-192-168-3-99-8080-2026-10-11-14_01_38.pdf）。動画ID、カバーの参加者、バージョンの補足に使っています。
- 動画IDを読み取れた曲はYouTubeの公開oEmbed情報と照合しています。例えばMIMIの[星涙哀歌](https://www.youtube.com/watch?v=Wiz0Ap2ge5U)、[SorrowChat](https://www.youtube.com/watch?v=r5xaccIl1Ps)です。

同一の曲名・アーティスト・バージョンは統合し、カバーや別バージョンは別項目として残しています。英訳されたファイル名は画像の曲名へ直し、「愛言葉IV」と記載されたDECO*27の動画はYouTube上の「愛言葉V」へ訂正しました。「誰も見てない夢を見る」は公式動画情報の「誰も見てない夢を見ろ」へ訂正しています。

整理後のデータは163件、65組です。88件に照合できた動画のリンクを設定し、残り75件には曲名・アーティストによるYouTube検索リンクを設定しています。直接リンクは公式チャンネルに限らず、資料で指定されたカバー動画・投稿動画も含みます。リンク先の将来の公開状態や地域制限を保証するものではありません。

PDFの「アーティスト不詳・タイトル不明」3ファイルと、歌い手を特定できない「回る空うさぎ」の弾き語り版は掲載していません。追加の画像で読める「ヒッチコック」「都落ち」「サマータイムレコード」は独立した確認済みの曲名として採用し、不明ファイルとの対応関係は推測していません。元のPDF・画像・音源そのものはリポジトリや配布物へ含めません。

## 保存と編集

初期データは `xserver/public/api/music-library.json` に保存しています。公開・管理のプロフィール取得APIは、音楽欄が空で未設定の場合だけこのデータを補います。取得時にSQLiteへ書き込むことはありません。既存の音楽一覧がある場合は、その一覧を優先します。

管理画面で保存すると通常のプロフィールと一緒にSQLiteへ保存され、その後は保存された音楽一覧を使用します。すべての曲を削除して保存した場合も、初期データが復活しないように内部の設定済みフラグを保存します。フラグはAPIのプロフィールレスポンスへ公開しません。音楽欄は最大200件まで編集できます。

編集画面の音楽欄全体は初期状態で折りたたみます。曲数の付いた「Music / 音楽」を開くと、各曲の編集・追加・削除ができます。閉じても入力内容は保持され、プロフィールの保存対象に含まれます。

Skills・Personalは公開ページと編集画面から外しています。既存の保存データと入力形式は互換性のため保持しています。

## 配布

通常の更新パッケージに初期データJSONも含まれるため、追加のインポート操作は不要です。`dist/update.zip` の中身を既存の `public_html` へ上書きして更新します。既存の `uploads` と `portfolio-private` は保持します。
