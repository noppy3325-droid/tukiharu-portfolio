# 記号から書式へ切り替わるブログエディター

Blogの本文は、Notionのように行頭の記号で書式を切り替えられます。記号を入力し、スペースを押すとその行が見出しやリストになります。全角の記号・数字・スペースにも対応しています。

| 行頭に入力してスペース | 書式 | 全角の例 |
| --- | --- | --- |
| `#` | 大きな見出し | `＃` |
| `##` | 中くらいの見出し | `＃＃` |
| `###` | 小さな見出し | `＃＃＃` |
| `-` / `*` / `+` | 箇条書き | `－` / `＊` / `＋` |
| `1.` | 番号付きリスト | `１．` |
| `>` | 引用 | `＞` |
| バッククォート3つ | コードブロック | 全角バッククォート3つ |
| `---` | 区切り線 | `－－－` |

本文中の記号やコードブロック内の記号では切り替えません。日本語を変換中は待ち、入力を確定してから処理します。変換直後のBackspaceで記号に戻せます。通常の取り消し・やり直しはCtrl+Z / Ctrl+Shift+Z、MacではCommandを使います。リストの空行でEnterを押すと本文に戻ります。コードブロックからはCtrl+Enter / Command+Enterで抜けられます。

太字は`**文字**`、斜体は`*文字*`、インラインコードはバッククォートで文字を囲んでも指定できます。記号を覚えていなくても、段落の選択欄とボタンで同じ書式に切り替えられます。「画像」ボタンを押すと、直接ファイル選択が開きます。必要に応じて隣の「画像の説明と画質設定」を先に開き、説明・画質を設定できます。設定欄は本文より上に表示します。

## 何を使い、なぜ変えたか

以前はブラウザの`contentEditable`と`document.execCommand`で編集していました。現在は[Tiptap](https://tiptap.dev/docs/editor/getting-started/install/react) 3.32.0（ProseMirrorベース）を使います。編集内容・選択位置・取り消し履歴を文書モデルで管理でき、日本語入力中の扱いやリスト編集などを個別に作り直す範囲を減らせるためです。

- [RichTextEditor.tsx](../client/src/components/RichTextEditor.tsx)：編集画面、現在の書式、画像挿入、親フォームとの連携。
- [blogEditor.ts](../client/src/lib/blogEditor.ts)：使う書式と、全角・半角の入力ルール。
- [LazyRichTextEditor.tsx](../client/src/components/LazyRichTextEditor.tsx)：Blogタブを開いたときに編集コードを読み込む。
- [blog-editor.css](../client/src/blog-editor.css)：静かなノート風の文字組、ツールバー、公開本文のコードや引用。

入力ルールは文書の行頭で一致した部分だけを置き換えます。全角を半角に変換するのは番号付きリストの開始番号だけで、本文全体を正規化しません。記事のタイトルが`h1`なので、本文の大・中・小の見出しは`h2`・`h3`・`h4`として保存します。

保存先は従来と同じHTML文字列です。既存の見出し・段落・太字・斜体・リンク・リスト・画像を編集に読み込み、同じPHP APIからSQLiteへ保存します。記事を切り替えた場合は編集インスタンスも切り替え、別記事の取り消し履歴が混ざらないようにしています。画像の挿入位置は編集トランザクションに追従させ、アップロード中の入力で位置がずれにくいようにしています。

PHPと旧Nodeアダプターの両方で、安全な書式の許可リストを合わせています。小見出し・コード・区切り線・取り消し線・リスト開始番号を保持し、スクリプト、イベント属性、任意のクラスや危険なURLを除去します。コードの山括弧は文字として保存・表示します。DBの移行は不要です。

## PHP 8.3.36

現在のXServerの指定はPHP 8.3.36です。[公式変更履歴](https://www.php.net/ChangeLog-8.php#8.3.36)と8.3の互換性変更を確認し、このアプリの既存APIにバージョン変更専用の修正が必要な箇所は見つかっていません。今回のPHP変更は、新しい本文書式を安全に保存するための許可リストの更新です。

ローカル検証には、PHP公式のWindows版8.3.36をハッシュ確認のうえテスト用フォルダーに展開しています。OSのPHPやサーバー設定を置き換えず、その実行ファイルでPHP・SQLiteのテストを実行します。必要な拡張はPDO SQLite・GD・DOM/libxml・fileinfo・mbstring・sessionです。公開サーバーのApache設定や実機での日本語キーボードの動作は、ローカルの検証とは別です。

## 確認方法

`pnpm check`、`pnpm test`、`pnpm build`、`pnpm test:release`、`pnpm test:xserver`で型・既存機能・配布物・PHP通信を確認できます。PHPを切り替える場合は`PHP_BIN`に実行ファイルを指定します。

`pnpm test:editor`は、ビルド済みファイルと独立したテスト用SQLiteを使うChrome検証です。`PLAYWRIGHT_MODULE`で利用するPlaywrightの場所を指定できます。半角・全角の入力、ChromeのIMEイベント再現、取り消し、保存・再読込・公開表示、旧記事、6画面幅を確認します。テストはローカル8080番を使用するため、他のローカルサーバーを停止してから実行してください。

2026年10月27日に、型チェック、121件のVitest、配布処理3件、PHP 8.3.36での40項目とAPI統合検証、ビルドを確認しました。Chromeでは全角・半角の入力、IMEイベント再現、Backspaceと取り消し・やり直し、リスト終了、コード内の記号、旧HTML、画像アップロード・保存・再編集、公開表示を確認しています。320・375・430・768・1024・1440pxで横方向のはみ出しがなく、タッチ操作と44pxのボタンも確認しました。実際の日本語IMEキーボード、実機Safari、公開XServerへの反映は未検証です。

2026年10月31日に、画像ボタンが設定欄を開くだけで、ファイル選択が直接開かない問題を修正しました。設定欄も本文の下からツールバーの近くへ移しています。以前の検証はファイル入力に直接ファイルを設定していたため、ボタンからファイル選択が開くかを確認できていませんでした。現在は実際のファイル選択イベントをクリック・Enterキー・タッチで確認し、キャンセル、模擬的な通信エラー後の同一ファイル再選択、実際のPHPでの画像アップロード・保存・再読込まで検証しています。型チェック、121件のVitest、ビルド、6画面幅での検証も通過しました。公開XServerへの反映と実機Safariは未検証です。

## 記事冒頭のカバー写真

公開記事では、本文内の最初の写真をタイトルより上のカバーとして表示します。元の位置には重複表示せず、2枚目以降の写真と本文・説明文は残します。縦横比を保ち、写真を切り抜かず画面幅に合わせます。写真のない記事にはカバー枠を表示しません。保存したHTMLは変更しないため、既存の記事にも反映されます。編集画面で最初の写真を変更すると、公開記事のカバーも変わります。


## 公開記事の読みやすさ

記事本文の手前にある「読みやすさ」で、閲覧者が文字サイズと行間を選びます。設定はそのブラウザに保存され、別の記事でも使われます。「標準に戻す」で16px相当・1.9倍に戻せます。

管理画面では「段落の配置」から文字揃えを編集できます。以前の記事に保存された文字サイズ・行間は、記事の編集データとして保持されます。公開ページの表示には閲覧者の設定を適用します。
